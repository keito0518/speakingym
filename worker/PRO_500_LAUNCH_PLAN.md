# Speakingym 初期Pro（月500円）の採用候補 — 2026-10-16

> **本番課金未開始・価格は暫定・試算利益は保証ではない。** 計測値なしでPro販売を開始しない。AIモデルは当面`gemini-3.5-flash-lite`のまま。Groqへの切替は行わない。

## 1. 今回の方針（検証用のPro制御を先に実装）

- **Pro（月500円、税込を想定）**：1か月 **600 AIリクエスト（往復を目標）**、AI先生 **20回**、日次回数上限なし。毎月1日00:00 JSTリセット。
- AI会話では **1セッション7分以内、20リクエスト以内**。1日に何度でも新セッションを作れるが、月間リクエスト枠を消費する。
- Geminiエラー時も既存実装では会話リクエスト枠を消費し得る。販売前に正常時だけカウントする設計や障害時の取り扱いを確定・表示すること。
- **現在のFree betaは変更しない**：AI会話1日5セッション、AI先生1日3回、60秒チャレンジ・反復復習は無制限。
- **有料ローンチ時のFree候補（まだ未実装）**：AI会話1日1セッションかつ月10セッション、AI先生月3回。旧利用者への告知、タイミング、納得感を検討。無料枠を勝手に今すぐ減らさない。
- Proは現時点で運営者がD1上から検証用にのみ指定。支払者の自動Pro付与、Stripe、請求・解約、返金などは未実装。

**なぜFreeの再設計が必要か？** 今のFreeなら30日×5セッション×最大20リクエスト=理論上3,000リクエスト/月。Proの月600リクエストより多く使える。Pro販売前に魅力と公平性が逆転しないようにする。

## 2. 原価の計算（あくまで仮定）

Gemini 3.5 Flash-Lite有料API: 入力$0.30/百万トークン、出力（thinking含む）$2.50/百万トークン。ドル円¥150を仮定。
- **1 AIリクエスト**: 入力3,000、出力450トークン → ¥0.30375
- **Pro会話600回**: ¥182.25
- **AI先生1回**: 入力2,500、出力1,200トークン → ¥0.5625
- **AI先生20回**: ¥11.25
- **Stripe決済手数料**: 3.6% + Billing0.7%と仮定 → ¥21.50 / ¥500
- **消費税相当の留保**: 税込500円の10/110=¥45.45（納税義務・仕入税額控除によって変動）

**有料会員1人を上限まで利用した場合の仮の残額:**
`500 − 182.25 − 11.25 − 21.50 − 45.45 = 約¥239.55/月`。

- トークン量2倍 → `500 − 387 − 21.50 − 45.45 = 約¥46.05`。
- トークン量2.5倍 → `500 − 483.75 − 21.50 − 45.45 = 約−¥50.70`。
- このため**約2.24倍のトークン量が損益分岐**（Freeコスト・インフラ・人件費は全て除外）。この水準より前から経済性が悪化する可能性がある。
- 売上500円のうち、税抜売上・決済手数料、サブスク解約、返金、AI原価以外の運営費、Freeユーザーの原価を別途計算すること。
- Freeユーザーが多いとProの残額がFree原価補填に使われるため、Pro単体が黒字でも事業全体では赤字になり得る。

## 3. 実装済み（GitHubのみ、デプロイ・実機試験は別）

- `worker/plan-limits.js`: 現行Freeを維持。Proの月600リクエストとAI先生20回をD1 SQLite原子的SQLで制御。日付判定はJSTの暦月（`day`文字列の月範囲）、セッション開始月をまたぐリクエストは新セッションが必要。
- `worker/ai-worker.js`: Pro上限のエラーコード `monthly_turn_limit` と `monthly_teacher_limit` を返す。制限を超えたGeminiリクエストは拒否する。
- `/entitlement`: Proの月間利用数、残数を画面で表示するためのフィールド `limits.monthlyTurns`, `limits.monthlyTeacher`, `used.monthlyTurns`, `used.monthlyTeacher` を返す。
- `plan-usage.js` / `account-sync.js`: 月間残数とリセット日、上限案内を表示。
- `worker/plan-limits.test.mjs` / `tests/plan-usage.test.mjs`: 上限と日付境界の回帰テストを追加。

DBスキーマは既存の`ai_sessions.turns`・`teacher_uses.day`を利用し、**新たなD1テーブルの作成は不要**。デプロイ前にGitHub Actionsとテスト用アカウントで検証し、現行Freeに影響がないか確認。
