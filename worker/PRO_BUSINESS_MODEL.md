## 2. 原価モデル（全て**仮定**、実測ではない）

為替レート **$1 = 150円と仮定**（現在の実勢レートではない）。
- 1往復の平均: 入力 3,000 tokens、出力 450 tokens（thinking含む）
- 1セッション: 平均 7 往復（**既存コードの最大20リクエストより小さい**。20回使われた場合はこの想定より大幅に原価が上がる）
- AI先生1回: 入力 2,500 tokens、出力 1,200 tokens
- 単価: 1 AIセッション = `7 × (3000×0.30 + 450×2.50) ÷ 1,000,000 × 150` = **約¥2.13**
- 単価: AI先生1回 = `(2500×0.30 + 1200×2.50) ÷ 1,000,000 × 150` = **約¥0.56**

この値は平均ではなく**仮定入力から導いたシナリオ**。実測値がないので有料販売確定に使わない。現在Gemini無料APIからの実請求はこの金額ではない。Geminiに直接送るものは文字テキストで、ブラウザの音声認識・読み上げはこの課金単価に含めない。

## 4. 無料ユーザーを含む損益

Pro候補B ¥1,480。一般的な会員1人を「AIセッション50回/月・AI先生20回/月」と**仮定**:
- AI原価: 50×2.12625 + 20×0.5625 = **約¥118/月**
- Stripe: 1,480×4.3%= **約¥64/月**
- 1人あたり利益寄与: **約¥1,299/月**（Free原価・共通固定費等の前）

Free1人を「AIセッション12回/月・AI先生3回/月」と**仮定**:
- 有料API利用時の原価 = **約¥27.2/月**
- Freeが1,000人なら **約¥27,200/月**。Free全員が1日枠を毎日使用した場合、現在のFree設計では1人最大で概算 **約¥370/月** に達し得る。

月5万円の営業利益寄与目標（税・人件費など除く）：
- Freeがほぼいない場合 → 約39人の通常利用Pro会員が必要。
- Free 1,000人（上記平均）・Workers Paid¥750/月を仮定 → **約61人**の通常利用Pro会員が必要。
- 無料APIだけでの提供は無料枠超過時に止まるので、「料金を払えば安定して使える」と約束できない。

## 5. 有料提供前に必須の安全設計

1. **Gemini実測値**: API responseの`usageMetadata.promptTokenCount`, `candidatesTokenCount`, `thoughtsTokenCount`, `totalTokenCount`相当を記録する（利用モデルのレスポンス仕様確認が必要）。セッション種別、成功/失敗、トークン数、日別合計を収集。個人の英文原文は原価調査のためには保存しない。
2. **プラン上限をサーバーで設定**: Proの`null`（無制限）は販売開始までに廃止。「1日」「1か月」の両方をD1トランザクション整合性が保てる方法で記録。Freeへの月次上限追加は既存ユーザーへの表示・告知設計を先に行い、**今回勝手に変更しない**。
3. **原価の停止ライン**: 1セッション最大20ターンの現仕様だと、仮定7ターンと比較して最大で約2.9倍の会話往復となりうる。追加の月間AIターン/トークン上限や公平利用条件をユーザーに明示したうえで実装する（広告にない隠れ上限は作らない）。 Geminiの費用・レート異常検知、サービス全体とユーザーごとの上限、課金前のテスト環境、運営者の停止スイッチ。Gemini APIは請求先の形式（Prepay / Postpay）に注意し、Postpayの予算通知をハードキャップだと誤解しない。
4. **Stripe安全性**: Stripe Checkout、Customer Portal、Webhookの署名検証・重複イベント対策・解約/未払い/返金処理、UIDとの厳密なマッピング。決済成功のクライアント自己申告では`pro`にしない。
5. **UI上の整合性**: 決済公開前に`plans.html`で「料金未定」「募集中ではない」と告知を継続。セッション残数は`/entitlement`に依存し、日次・月次上限双方の表示に合わせる。
6. **品質・競争優位**: Proは単に回数を増やすだけでなく「自分が言えなかった表現の蓄積」「1週間の振り返り」「弱点から次のお題を提案」など“知識があるのに話せない人向け”の導線を実際に作る。
7. **支払い前の有料需要検証**: 明確な月額と上限を提示した「興味あり」アンケート/待機リストで意向を見る。成約可能性を調べるが、**申し込み・課金に見える誤認UIは作らない**。
